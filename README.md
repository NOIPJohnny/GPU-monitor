# GPU Monitor

[English](README.en.md)

一个用于通过 SSH 查询多台机器 GPU 状态的 Flutter 桌面小工具。

![interface](assets/interface.png)

## 功能

- 从 `~/.ssh/config` 读取主机配置。
- 通过 SSH 执行 `nvidia-smi`，查询 GPU 利用率、显存、温度和功耗。
- 按主机展示查询结果，并区分正常、无 GPU、错误和加载状态。
- 在每张 GPU 卡片底部折叠展示进程详情，包括 PID、用户、显存占用、运行时间和命令行。
- 在支持的 Linux 主机上展示进程级 SM / MEM 利用率；不支持 `pmon` 的环境会自动降级为 `N/A`。
- 可在设置中开启 CPU 监控，按主机展示 CPU 利用率、占用核心数、系统内存、逻辑核心数和负载。
- CPU 卡片可折叠展示 CPU 占用最高的进程，包括 PID、用户、CPU / MEM 占用、内存、运行时间和命令行。
- 在资源概览中按机器聚合展示空闲 GPU，并按用户聚合展示 GPU 占用。 CPU 数据仅显示在各主机区域，不会加入资源概览。
- 支持选择启用的主机、手动刷新、自动刷新间隔、浅色/深色主题和语言中英文切换。
- 支持为每台主机开启状态提醒：服务器整体状态连续两次采样确认从忙碌变为空闲或从空闲变为忙碌后，同时发送 Windows/macOS 系统通知和邮件。
- 可选择在关闭窗口后继续后台运行：Windows 隐藏到系统托盘，macOS 保留在 Dock，监控与提醒不会中断。

## 状态变化提醒

在设置页可以点击“发送测试系统通知”验证 Windows/macOS 的本地通知和权限。填写全局 SMTP 配置后，还可以在保存前点击“发送测试邮件”验证当前表单中的配置。测试成功后保存配置，再为需要监控的服务器打开“提醒 GPU 忙闲变化”。开启提醒会自动开启自动刷新。

提醒仅在应用进程持续运行、电脑未休眠、网络和 SSH 可用且自动刷新开启时工作。首次成功查询只建立状态基线，不发送通知；之后服务器状态连续两次采样一致才会确认变化。确认变化后，系统通知与邮件会独立发送；SMTP 暂时失败不会阻止系统通知。服务器只要有一张 GPU 符合现有空闲规则，就视为整体空闲。

需要关闭主窗口后仍接收提醒时，请在“设置 → 后台运行”中打开“关闭窗口时继续后台运行”。Windows 可单击托盘图标恢复窗口，右键托盘图标后选择“退出 GPU Monitor”才会真正退出；macOS 可单击 Dock 图标恢复窗口，并通过应用菜单退出。

### iCloud 邮箱配置

1. 确保 Apple 账户已开启双重认证。
2. 登录 [Apple 账户](https://account.apple.com/)，进入“登录与安全性”→“App 专用密码”，创建名为 `GPU Monitor` 的专用密码。
3. 在应用中填写：
   - SMTP 服务器：`smtp.mail.me.com`
   - 端口：`587`
   - 加密方式：`STARTTLS`
   - SMTP 用户名：完整 iCloud 邮箱，例如 `name@icloud.com`
   - 应用专用密码 / 授权码：上一步生成的密码，不是 Apple 账户登录密码
   - 发件地址：留空或填写同一个完整 iCloud 邮箱
   - 收件人：接收提醒的邮箱，可以仍是该 iCloud 邮箱
4. 点击“发送测试邮件”；确认收到后点击“保存配置”，再打开服务器提醒开关。

如果修改或重置 Apple 账户主密码，已有应用专用密码会失效，需要重新生成并更新。参见 Apple 的 [iCloud Mail 服务器设置](https://support.apple.com/zh-cn/102525)和[应用专用密码说明](https://support.apple.com/zh-cn/102654)。

从源码构建 Windows 版本时，安全存储和系统通知插件要求 Visual Studio Build Tools 安装可选的 **C++ ATL（适用于最新 v143 生成工具，x86 和 x64）**组件；已编译的应用不要求用户单独安装该组件。
